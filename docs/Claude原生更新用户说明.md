# Claude Desktop 正式版：更新与老用户迁移

新用户首次完整解压正式安装包，申请并完成本机授权后运行「安装与更新」。新版安装器会登记 GitHub 更新市场，保留完整技能、三个知识库连接器和三个子代理。

## 以后如何更新

打开 **Plugins → Starsky amazon agent → Update**，有新版时按宿主提示更新，然后重开 Claude Desktop、新建会话。

已是最新版时按钮可能置灰。安装本版或运行一次修复包后，后台会在登录后及每30分钟核验签名版本，必要时刷新星空市场；用户无需逐版输命令。插件页暂未刷新时，可离开后重新进入；更新安装后请重开客户端、新建会话。

星空检查器只读取版本和签名、刷新星空市场，不请求安装插件，也不调用 AI。关机、休眠、离线时无法保证30分钟内发现；失败会保留失败状态，不会误报已是最新。Claude 自身的更新策略仍由宿主控制。原生 command 来源要求内置 Claude Code 至少 **2.1.229**，不满足时先升级 Claude Desktop。第三方模型/API 不决定市场更新权限。

## 旧本地安装只需迁移一次

1. 完整解压适合系统的 **Claude 原生更新修复包 1.0.4**。
2. **请在系统终端运行，不要让 Claude 代为运行。** Windows 运行「开启原生更新.bat」；Mac 运行「开启原生更新.command」。Mac 无法双击时，在终端输入 `bash `，拖入该文件再回车。
3. 按提示允许本机安装适配命令。适配器会校验签名、现有授权和目标发行，并将同名 `starskyclaude` 市场改为 GitHub 来源。不需要先删除插件。
4. 完全退出并重开 Claude Desktop，在新会话核对版本。插件页应只有一个星空；知识库连接器三个、子代理三个。
5. 以后使用插件页 Update，不需要逐版下载安装包或更换授权码。

已经迁移到 GitHub 的用户也运行一次本修复包：只修复更新重试并登记新版检查，业务版本保持不变，随后点击原生 Update。无需重新迁移或删除插件。

## 关闭或重新开启新版检查

双击修复包里的「关闭新版自动检查」，会移除 Windows 当前用户计划任务（系统拒绝登记时使用当前用户启动项作为备用）或 Mac 当前用户 LaunchAgent；无需管理员。重新启用时双击「开启新版自动检查」。安装更新会保留用户主动关闭的选择。

安装后也可在 `~/.starsky-claude/native/` 找到这两个入口。状态文件 `discovery-last.json` 只记录版本、检查时间和成功/失败，不含授权码或 API 配置。未发现新版和网络检查失败会分别显示。

授权、模型/API、S5 接入配置、产品资料和广告终端数据保留。旧版本和迁移登记备份保留供恢复；失败时按提示处理，不自行删除这些目录。旧缓存暂时保留，清理须另行提示并由用户确认。

本适配包不签发或续期会员授权。有效会员沿用现有凭证；缺授权时先联系作者办理本机授权。会员到期不锁已安装内容，新版校验未通过不会替换当前完整插件，续费后再更新。
